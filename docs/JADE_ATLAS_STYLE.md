# Нефритовый атлас Kaskad

## Дизайн-система, редакционная подача и правила визуальной строгости

**Версия кодекса:** 1.0.0  
**Дата редакционного среза:** 2026-11-28  
**Область действия:** README, Markdown-документы, SVG-иллюстрации и диаграммы репозитория Kaskad.  
**Статус:** редакционный стандарт; не является математической аксиоматикой K3.

---

## 1. Художественная ось: дисциплина, след и неизвестное

Стиль строится на столкновении двух способов видеть математический объект.

- **Нефритовая дисциплина** — порядок, точность, повторяемость, границы, реестр коэффициентов и доказательства.
- **Янтарная экспедиция** — карта, следы, вопрос, переход между областями, поиск контрпримеров и неизвестных связей.
- **Обсидиановая основа** — тишина фона, на которой заметны структура и отклонения.
- **Магентовая аномалия** — редкое обозначение сбоя, противоречия или неподтверждённого участка. Она не означает научную новизну или истинность.

Это оригинальная редакционная интерпретация визуальных мотивов, переданных для проекта. Она не копирует чужие иллюстрации, логотипы, персонажные образы, цитаты или исходные HTML/CSS-шаблоны.

## 3. Типографика и ритм

GitHub управляет типографикой Markdown. Поэтому:

- основной текст использует стандартные шрифты интерфейса GitHub;
- формулы записываются в поддерживаемом математическом синтаксисе;
- технические идентификаторы можно выделять встроенным кодом;
- SVG использует системные семейства sans-serif и monospace;
- удалённые шрифты и внешние font-CDN запрещены для канонических иллюстраций;
- заголовки соблюдают иерархию: один H1, затем последовательные H2 и H3;
- вокруг формул, Mermaid-блоков, таблиц и раскрывающихся блоков оставляются пустые строки.

Сетка строится на кратных 8 px шагах, когда изображение содержит координатную или модульную композицию. В текстовом документе важнее читабельные интервалы, чем искусственное выравнивание.

## 4. Десять визуальных мотивов

Это не десять независимых тем оформления, а набор выразительных приёмов, выбираемых по содержанию документа.

| Мотив | Где применять | Форма подачи |
|---|---|---|
| Живая мандала | итерации, рекурсии, фракталы | статическая SVG-спираль или сетка; интерактивность выносится на отдельную страницу |
| Сад формул | определения и базовые тождества | воздух, короткий вывод, одна идея на блок |
| Космос чисел | константы, простые числа, последовательности | каталог точек, индексов и связей |
| Оригами логики | доказательства и переходы | раскрываемые шаги через HTML-элемент details |
| Поток Ци | преобразования и вычислительные процессы | направленная схема входа, операции и результата |
| Библиотека бесконечности | литература и первоисточники | реестр публикаций, авторов, дат и DOI |
| Нейронная гармония | когнитивные операторы и графы | типизированные узлы и подписанные рёбра |
| Архитектура Эйлера | основания и слои формализации | блок-схема уровней и зависимостей |
| Музыка чисел | периодичность, гармоника, колебания | волновая SVG-графика с явными параметрами |
| Путь исследователя | дорожная карта | этапы, статусы и проверяемые критерии завершения |

В README следует использовать не больше одного доминирующего образа на экранный раздел. Не нужно превращать каждую страницу в коллекцию декоративных карточек.

## 5. Архитектура страницы README

Рекомендуемый порядок:

1. оригинальный SVG-баннер и название;
2. короткое определение проекта;
3. канонические параметры K3;
4. один пример с позиционным разложением;
5. навигационная карта по документации;
6. статусы математических утверждений;
7. исследовательские и прикладные расширения;
8. атрибуция и лицензия.

Страница должна работать без JavaScript, удалённых скриптов, внешних картинок и облачного шрифта. В README допускаются SVG, таблицы, Mermaid и раскрывающиеся блоки, если они остаются понятными в обычном GitHub Markdown.

## 6. Правила для математики и нулей

Визуальная выразительность не должна менять содержание.

- У группы есть коэффициент и позиция.
- Символ k — разделитель групп, а не декоративный суффикс.
- Нулевая группа сохраняет свой позиционный вес.
- Строгая каноническая грамматика отделена от режима импорта K3-PAD.
- K3-RAW не переименовывается в каноническое число без явной операции интерпретации.
- Формулы сопровождаются областью определения и предпосылками.
- Перестановка, удаление или сжатие нулей и разделителей запрещены без доказательства эквивалентности соответствующего представления.
- Численное равенство, структурное равенство и равенство истории вычисления не смешиваются.

## 7. Диаграммы и изображения

**Разрешено:** оригинальные SVG, диаграммы Mermaid, таблицы, типографические формулы, простые геометрические сетки и локальные изображения с ясным происхождением.

**Не использовать в канонической документации:** удалённые GIF неизвестного происхождения, логотипы без разрешения, чужие персонажные изображения, скриншоты без атрибуции, внешние CDN, CSS-фреймворки, трекеры, счётчики без реальных измерений и анимацию, которая мешает чтению.

Встроенный SVG должен иметь viewBox, текстовый alt при вставке, достаточный контраст и не ссылаться на внешние ресурсы.

## 8. Статусы и визуальные маркеры

| Статус | Рекомендуемая метка | Что означает |
|---|---|---|
| Определение | DEFINITION | точное введение объекта |
| Доказано | PROVED | приведено доказательство при указанных предпосылках |
| Спецификация | SPECIFICATION | требование к формальной модели |
| Предложено | PROPOSAL | конструкция, нуждающаяся в дальнейшей проверке |
| Гипотеза | HYPOTHESIS | утверждение без завершённого доказательства |
| Открыто | OPEN | явно оставленная задача |
| Внешний источник | SOURCE | сведения принадлежат указанному первоисточнику |

Не заменяйте эти статусы цветом, эмодзи или формой баннера. Текстовая метка должна оставаться читаемой и при отключённых изображениях.

## 9. Запрещённые редакционные приёмы

- фиктивные числа коммитов, ошибок, тестового покрытия и «собранных CI»;
- утверждения «всё доказано», если доказана только часть;
- удаление отрицательных результатов, контрпримеров и оговорок;
- внешние зависимости только ради декоративного оформления;
- заголовки, которые обещают интерактивность в статическом README;
- изменение авторства, истории происхождения или ссылки на источник;
- смешивание авторской терминологии с общепринятой без пояснения.
