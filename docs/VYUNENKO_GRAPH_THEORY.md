# Теория графов Вьюненко

## Графы каскадов, остаточные деревья, доказательные зависимости и операционная семантика узлов

**Версия:** 0.2.0  
**Статус:** авторская исследовательская спецификация на основе классической теории графов. Ни одно новое свойство графа не считается теоремой без доказательства.

## 1. Общая модель

Для K3 используются несколько разных графовых объектов. Их нельзя объединять в один граф без типизации рёбер.

Общий ориентированный размеченный мультиграф:

\[
G=(V,E,s,t,\lambda_V,\lambda_E,w),
\]

где \(V\) — множество вершин, \(E\) — множество рёбер, \(s,t:E\to V\) — начальная и конечная вершины, \(\lambda_V,\lambda_E\) — метки вершин и рёбер, \(w:E\to W\) — веса, если они заданы.

Несколько рёбер между одинаковыми вершинами разрешены, если они выражают разные отношения. Неориентированный граф получается при отождествлении направления, а гиперграф допускает рёбра, инцидентные более чем двум вершинам.

## 2. Граф доказательных зависимостей

Определим

\[
G_{\mathrm{proof}}=(V_{\mathrm{proof}},E_{\mathrm{proof}}).
\]

Вершины: определения, аксиомы, леммы, теоремы, следствия, гипотезы и вычислительные сертификаты.

Типы рёбер:
- **uses** — результат использует определение или лемму;
- **implies** — доказательство выводит следствие;
- **refines** — новая формулировка уточняет прежнюю;
- **contradicts** — объект опровергает гипотезу;
- **verified-by** — утверждение имеет машинно проверяемый сертификат.

Граф зависимостей uses и implies для завершённого доказательного ядра должен быть ацикличным. Ребро contradicts не означает логического вывода и может соединять разные ветви исследования.

Если \(T\) — теорема, а \(\operatorname{Pred}(T)\) — её непосредственные зависимости, то проверка статуса \(T\) требует:

\[
\operatorname{Valid}(T)
=
\operatorname{ProofValid}(T)
\land
\bigwedge_{u\in\operatorname{Pred}(T)}
\operatorname{StatusAcceptable}(u).
\]

## 3. Дерево остатков K3

Зафиксируем \(B=1000\). На уровне \(r\ge0\) определим вершины

\[
V_r=\mathbb Z/B^r\mathbb Z,
\qquad B^0=1.
\]

На уровне 0 имеется единственный корень — класс по модулю 1.

Для класса \(x\in\mathbb Z/B^r\mathbb Z\) его \(B\) продолжений на уровень \(r+1\) имеют вид

\[
x_j=x+jB^r\pmod{B^{r+1}},
\qquad j=0,\ldots,B-1.
\]

Ребро соединяет \(x\) с каждым \(x_j\). Эти продолжения различны и каждое отображается в \(x\) при редукции по модулю \(B^r\).

Следовательно,

\[
|V_r|=B^r=1000^r,
\]

и каждая вершина имеет ровно 1000 детей. **Доказательство различности детей:** если \(j\ne j'\), то \((j-j')B^r\) не делится на \(B^{r+1}\), поскольку \(0<|j-j'|<B\). **Полнота:** любой класс уровня \(r+1\), лежащий над \(x\), отличается от представителя \(x\) на кратное \(B^r\), а коэффициент этого кратного однозначно определяется по модулю \(B\). Это дерево классов вычетов, а не граф текстовых строк.

Бесконечный согласованный путь задаёт элемент обратного предела

\[
\varprojlim_r\mathbb Z/1000^r\mathbb Z
\cong\mathbb Z_2\times\mathbb Z_5.
\]

## 4. Граф переноса

У сложения двух групп состояние переноса принадлежит множеству

\[
C=\{0,1\}.
\]

Пусть \(A,D\) независимо и равномерно распределены на \(\{0,\ldots,999\}\). Выходное состояние:

\[
c'=
\begin{cases}
1,&A+D+c\ge1000,\\
0,&A+D+c<1000.
\end{cases}
\]

Для одного шага точные количества пар \((A,D)\) таковы:

| Вход \(c\) | Выход 0 | Выход 1 |
|---:|---:|---:|
| 0 | 500500 | 499500 |
| 1 | 499500 | 500500 |

Всего пар в каждой строке \(1000^2=1000000\). Нормированная матрица переходов:

\[
P=
\begin{pmatrix}
1001/2000&999/2000\\
999/2000&1001/2000
\end{pmatrix}.
\]

Строка матрицы соответствует входящему состоянию переноса, столбец — выходящему; порядок состояний — 0, 1. Её стационарное распределение равно \((1/2,1/2)\), а собственные значения — \(1\) и \(1/1000\). Это относится к независимым равномерным группам в указанной модели. Для ограниченных, зависимых или неравномерных коэффициентов матрица будет иной.

**Подсчёт переходов.** При входе \(c=0\) выход равен 0 тогда и только тогда, когда \(A+D\le999\); число пар равно \(1+2+\cdots+1000=500500\). При входе \(c=1\) выход равен 0 тогда и только тогда, когда \(A+D\le998\); число пар равно \(1+2+\cdots+999=499500\). Остальные пары дают выход 1. Деление на \(1000^2\) даёт матрицу \(P\). Вектор \((1/2,1/2)\) стационарен; векторы \((1,1)\) и \((1,-1)\) дают собственные значения \(1\) и \(1/1000\). Граф переноса имеет две вершины и четыре взвешенных перехода. Если веса заменяются кратностями, используется матрица целых чисел

\[
M=
\begin{pmatrix}
500500&499500\\
499500&500500
\end{pmatrix}.
\]

## 5. Простые графы, раскраски и свойства

Для исследования структуры каскадов допускаются классические характеристики: связность и компоненты связности, деревья и леса, циклы и мосты, степени вершин, двудольность, планарность, регулярность, клики и независимые множества, расстояния и диаметры, хроматические числа.

Правильная раскраска графа — отображение \(c:V\to\{1,\ldots,q\}\), для которого

\[
c(u)\ne c(v)
\quad\text{для каждого ребра }\{u,v\}\in E.
\]

Хроматическое число \(\chi(G)\) — минимальное число цветов правильной раскраски. «Правильность» относится к раскраске, а не к особому классу «правильных графов».

## 6. Гиперграфы

Гиперграф \(H=(V,\mathcal E)\) имеет рёбра \(e\subseteq V\) произвольной мощности. Он может моделировать совместную зависимость теоремы от нескольких определений или многогрупповую операцию, где одна связь одновременно включает более двух объектов.

Для гиперграфа полезны размер ребра, степень вершины, пересечение гиперрёбер, инцидентностная матрица, трансверсаль и покрытие.

Гиперграф не следует сводить к обычному графу без указания способа преобразования: разные проекции сохраняют разные свойства.

## 7. Спектральная теория

Для конечного неориентированного графа с матрицей смежности \(A\) и диагональной матрицей степеней \(D\) лапласиан задаётся формулой

\[
L=D-A.
\]

Для невзвешенного неориентированного графа \(L\) симметричен и положительно полуопределён. Число нулевых собственных значений равно числу компонент связности.

Для ориентированных или несимметричных взвешенных графов эти свойства нельзя переносить автоматически. Сначала задаётся конкретный лапласиан и соглашение о нормировке.

## 8. Граф когнитивных функций

Операторы распознавания, сравнения, классификации, вывода и пересмотра из документа [Когнитивные функции Теории Вьюненко](VYUNENKO_COGNITIVE_FUNCTIONS.md) образуют типизированный граф переходов.

Вершина хранит сигнатуру \(F:X\rightharpoonup Y\), предусловие и постусловие, сложность, инварианты и статус доказательной проверки.

Ребро \(F\to G\) разрешено, когда выходной тип \(F\) совместим со входным типом \(G\). Циклы допускаются для повторного анализа; цепочки доказательства остаются ацикличными.

2. Получить точные спектры выбранных графов переноса и расширенных автоматов.
3. Изучить графы сложения нескольких каскадов.
4. Построить гиперграф доказательных зависимостей.

6. Установить, какие свойства сохраняются при переходе между конечными уровнями и обратным пределом.

## 11. Операционная семантика триадного каскада

Категориальная склейка локальных паспортов задаётся в [спецификации высших структур K3](K3_HIGHER_STRUCTURES_AND_SEMANTIC_LAYERS.md), §4. Здесь фиксируется её операционная сторона: состояния узлов, эффекты вычислений, контекст зависимостей и критерии завершения.

### 11.1. Статусы узла и четырёхзначные предикаты

Операционный статус узла принадлежит множеству

\[
S_{\mathrm{node}}=
\{\mathsf{NEW},\mathsf{DEFERRED},
\mathsf{BLOCKED\_GUARD},\mathsf{BLOCKED\_CONFLICT},
\mathsf{CONVERGED}\}.
\]

Смысл статусов:

| Статус | Содержание |
|---|---|
| \(\mathsf{NEW}\) | вычисление ещё не выполнялось |
| \(\mathsf{DEFERRED}\) | результат пока не определён из-за отсутствующих зависимостей или данных |
| \(\mathsf{BLOCKED\_GUARD}\) | подтверждённое предусловие/охранное условие не выполнено |
| \(\mathsf{BLOCKED\_CONFLICT}\) | одновременно получены несовместимые свидетельства или ограничения |
| \(\mathsf{CONVERGED}\) | результат вычислен и прошёл все заявленные проверки для текущего поколения входных данных |

Эти статусы не совпадают с четырёхзначным результатом логического предиката. Для охранного условия применяется семантика свидетельств:

| Значение | Положительное свидетельство | Отрицательное свидетельство | Действие каскада |
|---|---:|---:|---|
| \(\mathbf T\) | есть | нет | разрешить следующий шаг |
| \(\mathbf F\) | нет | есть | перейти в \(\mathsf{BLOCKED\_GUARD}\) |
| \(\mathbf U\) | нет | нет | отложить узел: \(\mathsf{DEFERRED}\) |
| \(\mathbf B\) | есть | есть | зафиксировать конфликт: \(\mathsf{BLOCKED\_CONFLICT}\) |

Значения можно кодировать парами \((e^+,e^-)\). Поэтому отсутствие свидетельств (\(\mathbf U\)) не означает опровержение (\(\mathbf F\)), а конфликт (\(\mathbf B\)) нельзя разрешать произвольным выбором одного свидетельства. Статус хранится вместе с поколением входных данных, чтобы новый вход запускал явную повторную оценку, а не переписывал историю старого прохода.

Переход \(\mathsf{DEFERRED}\to\mathsf{CONVERGED}\) допустим после поступления недостающих данных и повторного прохождения охранных и алгебраических проверок. Снятие блокировки или конфликта также требует нового свидетельства, изменения входного поколения либо документированной политики разрешения; молчаливое удаление обструкции запрещено.

### 11.2. Журнал обструкций и доказательств

Пусть \(O^*\) — множество конечных последовательностей обструкций, а \(P^*\) — множество конечных последовательностей записей ProofChain. Их декартово произведение

\[
J=O^*\times P^*
\]

образует моноид относительно покомпонентной конкатенации

\[
(o_1,p_1)\otimes(o_2,p_2)
=(o_1\mathbin{+\!\!+}o_2,\ p_1\mathbin{+\!\!+}p_2),
\]

с единицей \(e_J=(\varepsilon,\varepsilon)\). Ассоциативность следует из ассоциативности конкатенации конечных последовательностей.

Журнал не является самим статусом. Статус характеризует исход вычисления, а \(J\) хранит путь, причины остановки, свидетельства и происхождение локальных вкладов. Объединение журналов не отменяет обструкции и не повышает доказательный статус результата автоматически.

### 11.3. Каскадная монада как композиция эффектов

Для множества узловых состояний \(S\), причины остановки

\[
\mathsf{Stop}
=\mathsf{Deferred}(D)
+\mathsf{GuardBlocked}(G)
+\mathsf{Conflict}(O)
\]

и моноида журналов \(J\) зададим вычисление

\[
\mathbb K(X)
=
S\longrightarrow
\bigl(\mathsf{Either}(\mathsf{Stop},X)\times S\times J\bigr).
\]

Это стек трансформеров \(\mathsf{ExceptT}\ \mathsf{Stop}\ (\mathsf{StateT}\ S\ (\mathsf{Writer}\ J))\ X\), то есть стандартная композиция short-circuit, state и writer в указанном порядке. При такой записи состояние \(S\) и журнал сохраняются даже при остановке.

Единица монады:

\[
\eta_{\mathbb K}(x)(s)
=(\mathsf{Right}(x),s,e_J).
\]

Пусть

\[
m(s_0)=(\mathsf{Right}(x),s_1,j_1).
\]

Тогда связывание определяется выполнением следующего вычисления из обновлённого состояния:

\[
(m\bind f)(s_0)=
\begin{cases}
(\mathsf{Left}(q),s_1,j_1),
&
m(s_0)=(\mathsf{Left}(q),s_1,j_1),
\\[2mm]
(r,s_2,j_1\otimes j_2),
&
m(s_0)=(\mathsf{Right}(x),s_1,j_1),\
f(x)(s_1)=(r,s_2,j_2).
\end{cases}
\]

В первой ветви последующее вычисление не запускается, но состояние и журнал сохраняются. Во второй ветви журналы соединяются моноидальной операцией. Умножение \(\mu_X:\mathbb K(\mathbb K(X))\to\mathbb K(X)\) разворачивает вложенное вычисление тем же правилом: внутренний шаг запускается только при внешнем результате \(\mathsf{Right}\), а состояния и журналы композиционно передаются дальше.

Монадические законы наследуются от выбранной композиции стандартных state-, exception- и writer-эффектов при указанных операциях и порядке композиции. При смене порядка эффектов, изменении короткого замыкания или нестандартном объединении обструкций законы единицы и ассоциативности необходимо проверить заново. Набор статусов сам по себе монады не образует.

Статусы \(\mathsf{DEFERRED}\), \(\mathsf{BLOCKED\_GUARD}\) и \(\mathsf{BLOCKED\_CONFLICT}\) представляются причинами остановки; \(\mathsf{NEW}\) — исходным состоянием узла, а \(\mathsf{CONVERGED}\) — успешным результатом текущего поколения данных. Повторный запуск отложенного узла является новой операцией планировщика, а не продолжением уже завершившегося вычисления.

### 11.4. Локальная окрестность и комонадический контекст

Для узла \(v\) и выбранной схемы окрестности \(N_r(v)\) контекст можно записать как

\[
\mathbb W_G(X)(v)=
\bigl(v,N_r(v),X|_{N_r(v)},E|_{N_r(v)}\bigr).
\]

Он содержит центральный узел, соседние паспорта, внутренние и граничные рёбра и локальные условия зависимостей. Чтобы этот контекст образовал комонаду, должны быть определены:

- коединица \(\varepsilon:\mathbb W_G(X)\to X\), извлекающая значение в центральном узле;
- комультипликация \(\delta:\mathbb W_G(X)\to\mathbb W_G(\mathbb W_G(X))\), помещающая каждый локальный контекст в корректно вложенный контекст;
- законы коассоциативности и левой/правой коединицы.

Правило обрезания окрестностей на границе должно быть совместимо с повторным извлечением вложенных окрестностей. Поэтому \(\mathbb W_G\) здесь является кандидатом на комонадический контекст, а не объявленной комонадой до задания и проверки этих отображений и законов.

### 11.5. Критерии корректности и остановки

Проход каскада корректен, если одновременно соблюдаются следующие требования:

1. **Семиотическая честность.** Узел в статусе \(\mathsf{DEFERRED}\), \(\mathsf{BLOCKED\_GUARD}\) или \(\mathsf{BLOCKED\_CONFLICT}\) не маркируется как \(\mathsf{CONVERGED}\). Непроверенный результат не объявляется доказанным.
2. **Алгебраическая допустимость.** Исчисление \(\mathcal C_k\) применяется лишь к указанному носителю и при выполнении его предпосылок.
3. **Инвариантность.** Слияние паспортов сохраняет заявленные инварианты либо сопровождается проверяемым доказательством их трансформации или редукции.
4. **Когерентность.** Категориальные склейки удовлетворяют условиям на двойных и тройных пересечениях; склейка морфизмов проверяется отдельно.
5. **Конечная остановка.** Для нетривиальных переходов задан хорошо основанный ранг, который строго убывает, либо доказано монотонное продвижение в конечном по высоте частично упорядоченном множестве к неподвижной точке.

Например, лексикографический ранг в \(\mathbb N^k\) может служить мерой завершения, если каждый нетривиальный редукционный шаг строго уменьшает его. Для итераций на конечной решётке достаточно доказать, что последовательность строго возрастает или убывает по порядку до стабилизации. Одного факта конечности графа недостаточно: переходы могут образовать цикл.

Лимит \(W_{\max}\) волн является защитным бюджетом, но не доказательством сходимости. При его достижении незавершённые узлы сохраняют текущие статусы и обструкции; они не переводятся автоматически в \(\mathsf{CONVERGED}\).

## 12. Контрольный пример: отложенный узел, CRT и конфликт

Три сценария ниже иллюстрируют разные конечные состояния.

- В \(\mathbb Z/6\mathbb Z\) класс \(2\) — ненулевой делитель нуля: \(\gcd(2,6)=2\ne1\). Узел сначала откладывается при отсутствии остатка, а после поступления \(2\) проходит вычисление.
- Ограничения \(x\equiv2\pmod3\) и \(x\equiv4\pmod5\) совместны; их единственный класс решения по модулю \(15\) — \(14\).
- Ограничения \(x\equiv1\pmod4\) и \(x\equiv3\pmod4\) несовместны, поскольку \(4\nmid(3-1)\); узел получает \(\mathsf{BLOCKED\_CONFLICT}\).

Ниже приведён самодостаточный арифметический контрольный фрагмент. Он проверяет CRT и спектральную классификацию остатка, но не реализует весь графовый планировщик, систему локальных паспортов или монадический движок.

~~~python
from dataclasses import dataclass
from enum import Enum
from math import gcd


class Status(str, Enum):
    DEFERRED = "DEFERRED"
    CONVERGED = "CONVERGED"
    BLOCKED_CONFLICT = "BLOCKED_CONFLICT"


@dataclass(frozen=True)
class Congruence:
    residue: int
    modulus: int

    def __post_init__(self) -> None:
        if self.modulus <= 0:
            raise ValueError("modulus must be positive")


def generalized_crt(
    constraints: list[Congruence],
) -> tuple[int, int] | None:
    """Return (canonical residue, lcm of moduli), or None on conflict."""
    residue, modulus = 0, 1

    for item in constraints:
        next_residue = item.residue % item.modulus
        common = gcd(modulus, item.modulus)
        delta = next_residue - residue

        if delta % common:
            return None

        left = modulus // common
        right = item.modulus // common
        inverse = pow(left, -1, right) if right > 1 else 0
        step = ((delta // common) * inverse) % right if right > 1 else 0

        combined_modulus = modulus * right
        residue = (residue + modulus * step) % combined_modulus
        modulus = combined_modulus

    return residue, modulus


def classify_residue(value: int, modulus: int) -> str:
    if modulus <= 1:
        raise ValueError("modulus must be greater than one")

    residue = value % modulus
    if residue == 0:
        return "ZERO"
    if gcd(residue, modulus) == 1:
        return "UNIT"
    return "NONZERO_ZERO_DIVISOR"


def run_reference_scenarios() -> dict[str, object]:
    # First pass: the dependency has not supplied its residue.
    source_residue = None
    initial = Status.DEFERRED if source_residue is None else Status.CONVERGED

    # Second pass: a new input generation supplies residue 2.
    source_residue = 2
    final = Status.CONVERGED

    return {
        "u_mod6": {
            "initial": initial.value,
            "final": final.value,
            "residue": source_residue,
            "spectrum": classify_residue(source_residue, 6),
        },
        "u_crt15": {
            "status": Status.CONVERGED.value,
            "solution": generalized_crt([
                Congruence(2, 3),
                Congruence(4, 5),
            ]),
        },
        "u_conflict": {
            "status": Status.BLOCKED_CONFLICT.value,
            "solution": generalized_crt([
                Congruence(1, 4),
                Congruence(3, 4),
            ]),
            "obstruction": "gcd(4, 4) = 4 does not divide 3 - 1 = 2",
        },
    }


if __name__ == "__main__":
    for node_id, result in run_reference_scenarios().items():
        print(node_id, result)
~~~

Контрольные результаты:

- \(u_{\mathrm{mod6}}\): \(\mathsf{DEFERRED}\to\mathsf{CONVERGED}\), NONZERO_ZERO_DIVISOR;
- \(u_{\mathrm{crt15}}\): \((14,15)\);
- \(u_{\mathrm{conflict}}\): \(\mathsf{BLOCKED\_CONFLICT}\), решения нет.

Пример не доказывает общую аксиому пучка, корректность категориального спуска для произвольного сайта, законы комонады или универсальную остановку графового автомата. Эти свойства остаются самостоятельными доказательными обязательствами.
