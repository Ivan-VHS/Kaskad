# Автоматическая синхронизация Теории Вьюненко

> **Cascade Edition 1.0.0 · Scientific integrity:** автоматизация распространяет только документальные ссылки; она не повышает статус математических утверждений и не переносит исходный код.

**Версия источника:** K3 0.5.0  
**Состояние механизма:** workflow и скрипт входят в репозиторий. Наличие секрета и фактический запуск межрепозиторной синхронизации не подтверждены.

## Запуск

Workflow: [`.github/workflows/vyunenko-ecosystem-sync.yml`](../.github/workflows/vyunenko-ecosystem-sync.yml)

Автоматический запуск выполняется после изменения канонической теории, CRT-пополнения, двухканальной геометрии, K3-M или реестра экосистемы в `main`. Доступен также ручной `workflow_dispatch`.

Скрипт [`scripts/sync_vyunenko_docs.mjs`](../scripts/sync_vyunenko_docs.mjs):

1. читает версию и перечень репозиториев из [реестра экосистемы](VYUNENKO_ECOSYSTEM_SYNC.v1.json);
2. проверяет allowlist из пяти репозиториев, политику `documentation_reference_only`, отсутствие runtime-зависимости и допустимые пути файлов;
3. обновляет локализованные README и индекс, создаёт математическую справку с ссылками на CRT, двухканальную геометрию, K3-M и реестр утверждений;
4. создаёт отдельную ветку и Draft PR для каждого изменяемого репозитория;
5. актуализирует существующий PR той же версии вместо создания дубликата.

Ни одна запись напрямую в целевую `main` не выполняется. Workflow на стороне Kaskad имеет только `contents: read`; межрепозиторные изменения выполняются отдельным fine-grained token и только через reviewable PR.

## Однократная настройка доступа

В настройках репозитория **Ivan-VHS/Kaskad** требуется Actions secret:

`IVAN_VHS_SYNC_TOKEN`

Минимальные права fine-grained token для каждого из пяти разрешённых репозиториев:

- **Contents: Read and write**
- **Pull requests: Read and write**

Allowlist в скрипте фиксирован: `Ivan-VHS/Pytyliki`, `Ivan-VHS/Reaper`, `Ivan-VHS/OPlague`, `Ivan-VHS/VentuSample`, `Ivan-VHS/DAK`. Токен не должен помещаться в файлы, логи, README или manifest.

При отсутствии секрета workflow проверяет синтаксис скрипта и исходный manifest, записывает предупреждение в Job Summary и не выполняет никаких межрепозиторных записей. По содержимому репозитория нельзя установить, настроен ли секрет в GitHub Actions; его наличие необходимо проверить в Settings → Secrets and variables → Actions.

## Границы и политика

- Сначала обновляется канонический Kaskad; затем изменения предлагаются отдельными Draft PR в зависимые репозитории.
- Автоматизация меняет только разрешённые документальные ссылки/заметки/индексы.
- Исходный код, runtime/build-зависимости, API/ABI, схемы данных, аппаратная логика и лицензии не переносятся.
- Attribution, copyright, LICENSE, NOTICE и авторские сведения целевого репозитория сохраняются.
- Проверки целевого репозитория и его собственное решение о слиянии обязательны.
- Утверждения по K3 используются только как документальная ссылка с указанием канонического источника; математическое переиспользование требует чтения доказательств и предпосылок.

**Автоматизация считается активной только после настройки секрета и успешного завершения workflow.**
