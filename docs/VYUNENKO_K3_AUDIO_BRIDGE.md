# Мост K3: позиционное представление аудиоданных и операторных цепочек

**Теория:** Вьюненко K3 · **Основание:** \(B=1000=10^3\)  
**Источник данных:** Ivan-VHS/VentuSample  
**Статус:** формальная спецификация отображений и типов; применение к исходному файлу без перекодирования является отдельной операцией

## 1. Цель моста

Мост связывает два уровня:

1. K3 — позиционная система целых чисел с коэффициентами \(0,\ldots,999\) и основанием \(B=1000\).
2. Аудиоданные — конечные последовательности целых или вещественных значений, измеряемые в кадрах, каналах, герцах, секундах и относительных амплитудах.

Связь не означает, что K3 заменяет типы аудиоданных, единицы измерения, DSP или PCM. Она задаёт строгие функции кодирования целочисленных величин, типизированные ключи, структуру данных и условия потери при явном квантовании.

## 2. Каноническое целочисленное отображение

Для \(n\in\mathbb N_0\) существует единственное конечное разложение:
\[
n=\sum_{i=0}^{m}a_iB^i,
\qquad a_i\in\{0,1,\ldots,999\},
\]
с обычным условием, что старший коэффициент ненулевой, если \(n>0\). Его текстовая запись — каноническое слово K3; символ \(k\) остаётся разделителем соседних групп.

Определим:
\[
\operatorname{K3Enc}:\mathbb N_0\to\mathcal L_{K3},
\qquad
\operatorname{K3Dec}:\mathcal L_{K3}\to\mathbb N_0.
\]
Для канонического слова \(w\):
\[
\operatorname{K3Dec}(\operatorname{K3Enc}(n))=n.
\]
Обратное тождество:
\[
\operatorname{K3Enc}(\operatorname{K3Dec}(w))=w.
\]
Обе формулы применяются только к строгой канонической записи; режимы K3-PAD и K3-RAW сохраняют свои уже определённые отдельные границы.

### 2.1. Примеры точного кодирования

| Значение / объект | Целое значение | Каноническая K3-запись | Типовая единица |
|---|---:|---|---|
| Основание K3 | 1000 | 1k | безразмерный параметр системы |
| Sample rate | 44100 | 44k100 | Hz |
| Sample rate | 48000 | 48k | Hz |
| Sample rate | 96000 | 96k | Hz |
| PCM16 код | 32767 | 32k767 | signed PCM code |
| Модуль минимального PCM16 кода | 32768 | 32k768 | signed PCM code magnitude |
| Предел FFT | 65536 | 65k536 | frames |

Код и единица образуют один типизированный объект. Например, пара \((44k100,\mathrm{Hz})\) означает 44 100 Hz. Строка 44k100 без единицы остаётся просто целым числом K3.

## 3. Знаковое расширение и PCM16

PCM16-код принадлежит множеству
\[
\mathbb S_{16}=\{-32768,-32767,\ldots,32767\}.
\]
Пусть знак числа хранится отдельно, а модуль кодируется K3:
\[
\operatorname{K3Signed}(s)=
\begin{cases}
(+,\operatorname{K3Enc}(s)),&s\ge0,\\
(-,\operatorname{K3Enc}(|s|)),&s<0.
\end{cases}
\]
Примеры:
\[
32767\leftrightarrow(+,\text{32k767}),
\qquad
-32768\leftrightarrow(-,\text{32k768}).
\]
Знаковое расширение должно сохранять единственное представление нуля без отрицательного нуля.

Декодированный аудиоотсчёт:
\[
x=\frac{s}{32768}.
\]
Следовательно, кодирование знакового целого \(s\) в K3 не теряет информацию о PCM16, а пара \((s,32768)\) точно сохраняет рациональную амплитуду. Сохранение только десятичной записи округлённого значения с плавающей точкой таким свойством не обладает.

## 4. Типизированные индексы и единицы

Один и тот же K3-код может быть числово точным, но семантически непригодным без типа. Поэтому вводятся разные типы:
\[
\begin{aligned}
&\mathrm{FrameIndex}(n,F_s),\\
&\mathrm{ChannelIndex}(c,C),\\
&\mathrm{SampleRate}(F_s,\mathrm{Hz}),\\
&\mathrm{Duration}(N,F_s,\mathrm{s}),\\
&\mathrm{Frequency}(f,\mathrm{Hz}),\\
&\mathrm{MidiTick}(\tau,P,\mathrm{tick}),\\
&\mathrm{Pcm16Code}(s),\\
&\mathrm{DspOrdinal}(j,\mathrm{catalogueVersion}).
\end{aligned}
\]
Каждое целочисленное поле может использовать K3Enc, однако типы не взаимозаменяемы. Число 44100 кадров не равно 44100 Hz и не задаёт длительность без указания \(F_s\).

Для аудиосигнала:
\[
\mathrm{AudioBuffer}=
(F_s,C,N,\{x_{n,c}\}).
\]
Его индексные ограничения:
\[
0\le n<N,\qquad 0\le c<C.
\]
Длительность определяется вычислением:
\[
T=\frac{N}{F_s}.
\]
Частота дискретизации — параметр временной координатной сетки, а не основание K3.

## 5. Мост от вещественного сигнала к точному целому коду

В общем случае \(x\in\mathbb R\) не имеет конечного целочисленного представления без выбора масштаба и правила округления. Поэтому нельзя без оговорки утверждать, что произвольный float «точно записан в K3».

Для аналитического экспорта можно явно задать фиксированный масштаб \(Q\in\mathbb N\) и округление к ближайшему целому:
\[
q_Q(x)=\operatorname{round}(Qx),\qquad
\widehat{x}_Q=\frac{q_Q(x)}{Q}.
\]
При конечном входном \(x\) и отсутствии переполнения:
\[
|x-\widehat{x}_Q|\le\frac{1}{2Q}
\]
для обычного округления к ближайшему, кроме деталей tie-breaking на точных полуцелых случаях, которые должны быть закреплены контрактом реализации.

K3 кодирует целое \(|q_Q(x)|\), знак хранится отдельно. Для демонстрационного масштаба \(Q=10^6\) граница абсолютной ошибки составляет не более \(5\cdot10^{-7}\) при оговорённом округлении.

**Это аналитическое отображение, а не изменение DSP-процесса VentuSample.** Оно не должно применяться к оригинальным буферам молча. Исходный float сохраняется либо фиксируется вместе со шкалой, методом округления, насыщением/отказом при переполнении и версией экспорта.

## 6. Тензорная запись конечного сигнала

Для \(N\) кадров и \(C\) каналов исходная матрица значений:
\[
X=(x_{n,c})\in\mathbb R^{N\times C}.
\]
При выбранном масштабе \(Q\) целочисленная матрица:
\[
Z_Q=(q_Q(x_{n,c}))\in\mathbb Z^{N\times C}.
\]
K3-кодирование применяется к каждому целому элементу, а не к измерительной единице:
\[
\mathcal K_Q(X)=
\big(\operatorname{K3Signed}(q_Q(x_{n,c}))\big)_
{0\le n<N,\;0\le c<C}.
\]

Сопутствующая индексная сетка:
\[
I(n,c)=(\operatorname{K3Enc}(n),c).
\]
Для каналов mono/stereo \(c\in\{0\}\) либо \(c\in\{0,1\}\). Сетка кадров и матрица данных — разные структуры: индекс не заменяет значение аудиоотсчёта.

### 6.1. Связь с тензорной главой K3

Для набора записей, содержащих несколько буферов или вариаций, допустимо задать тензор
\[
\mathcal X_{v,n,c}
\]
с осями вариации \(v\), кадра \(n\), канала \(c\). При сохранении исходной формы хранится также метаинформация \(F_s\), количество каналов, параметры генерации, seed, идентификатор алгоритма и формат PCM.

Такое представление не даёт права переставлять оси, менять местами каналы, удалять структурные нули или схлопывать кадры. Любая перестановка обязана сопровождаться явным отображением индексов и доказательством того, какая метрика/операция остаётся инвариантной.

Для конкатенации каналов или вариаций сначала сохраняются shape и координатные метки; голая последовательность целых чисел не является полным описанием исходного аудиодатасета.

## 7. Мост для каталога DSP и цепочки обработки

DSP-идентификатор — строковый ключ. Его ordinal от 1 до 133 является числом, но само по себе не является семантикой оператора. Типизированный реестр имеет вид:
\[
\mathcal D=
\{(id_j,\;j,\;family_j,\;model_j,\;variant_j,\;p_j)\}_{j=1}^{133}.
\]
Для версии каталога \(v\) определено отображение:
\[
\operatorname{DspId}_v\leftrightarrow
(j,\mathrm{model},\mathrm{variant},p_{\mathrm{default}}).
\]
Ordinal можно кодировать в K3 как целое, однако его интерпретация требует неизменного каталога и его версии. Например, ordinal 133 — это позиция записи в указанной версии реестра, а не 133-я степень основания или DSP-формула.

Цепочка обработки:
\[
\Gamma=(d_1,d_2,\ldots,d_q),\qquad 0\le q\le133,
\]
задаёт упорядоченный список узлов графа. Выход:
\[
x_q=T_{d_q}\circ\cdots\circ T_{d_1}(x_0).
\]
Для каждого узла сохраняются параметры \(A,T,R,M\in[0,1]\), версия оператора, состояние ошибки и отчёт. Порядок цепочки семантически значим. Перестановка DSP-узлов в общем случае изменяет результат.

Реестр 133 Atomic-Quantum функций должен иметь собственное пространство ID и отдельную версию. Совпадение количества элементов двух реестров не создаёт биекцию между DSP и симуляционными функциями.

## 8. Граф данных, граф вычисления и граф доказательств

Следует различать:
1. **граф данных** — узлы буферов, индексов, параметров и файлов;
2. **граф вычисления** — узлы операторов DSP и рёбра передачи сигналов;
3. **граф доказательств** — определения, леммы, теоремы, гипотезы, тесты и сертификаты.

Граф вычисления может быть направленным ациклическим графом для цепочки без обратной связи. Feedback-фильтр содержит внутреннее состояние и математически задаётся рекуррентной системой; он не должен ошибочно изображаться как безусловный DAG без явного узла задержки/состояния.

В графе доказательств используются типы рёбер, определённые в Теории графов Вьюненко: uses, implies, refines, contradicts, verified-by. Тест показывает поведение конечной реализации на конкретном множестве случаев; он не заменяет всеобщего доказательства формулы.

## 9. Инварианты и ограничения переноса

При переносе в Kaskad сохраняются следующие правила:

- порядок временных кадров и исходное количество каналов;
- знаковый код PCM16 и масштаб деления на 32768;
- единицы измерения \(F_s\), BPM, секунды, миллисекунды и герцы;
- отличия целого кода, рационального значения и float;
- параметры DSP и порядок композиции операторов;
- seed, variation index и версия генератора;
- версия pack manifest и происхождение источника;
- различие между анализатором и преобразователем;
- различие между каталогом DSP и Atomic-Quantum.

Ограничения VentuSample также сохраняются. Это офлайн-обработка. Перенос в математические документы не добавляет realtime audio callback, поддержку VST/AU, hardware driver, true-peak mastering, автоматическое распознавание BPM/тональности импортированного аудио или phase-vocoder time-stretch.

## 10. Примеры проверки моста

Для каждого контрольного теста проверяются код, декодирование, тип и единица:
1. \(44100\leftrightarrow44k100\), тип Hz.
2. \(48000\leftrightarrow48k\), тип Hz.
3. \(32767\leftrightarrow(+,\;32k767)\), PCM16.
4. \(-32768\leftrightarrow(-,\;32k768)\), PCM16.
5. \(N\) кадров и \(F_s\) герц дают duration \(N/F_s\), а не \(N\) секунд.
6. Любой float-перенос фиксирует \(Q\) и правило округления; исходный сигнал не изменяется.
7. Уникальные ID и ordinal двух каталогов проверяются независимо.
8. Изменение порядка DSP-цепочки не трактуется как инвариант без отдельного доказательства.
9. K3-канонизация обязана сохранять числовое значение и все позиционные нули, определённые каноническим вектором.

### Лемма 10.1. Точность целочисленного аудиокода

Каждый PCM16-код имеет единственное знаковое K3-представление при фиксированном правиле кодирования нуля.

**Доказательство.** Для \(s\in\mathbb S_{16}\) число \(|s|\) принадлежит \(\mathbb N_0\). По теореме канонического разложения K3 \(|s|\) имеет единственную конечную запись; знак восстанавливает исходный \(s\). Для \(s=0\) используется только положительное представление нуля. \(\square\)

### Лемма 10.2. Обратимость кодирования индекса кадра

Для любого допустимого индекса \(0\le n<N\):
\[
\operatorname{K3Dec}(\operatorname{K3Enc}(n))=n.
\]
Это прямое применение биективности строгого кодирования K3 на \(\mathbb N_0\). Тип FrameIndex и параметр \(F_s\) сохраняются отдельно.
