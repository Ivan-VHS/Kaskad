# Профиль структуры репозитория — Kaskad

**Общий стандарт:** [Ivan-VHS Repository Structure Standard, PR #239](https://github.com/Ivan-VHS/DAK/pull/239).

Kaskad применяет общий стандарт, сохраняя уже принятую структуру математического корпуса. Каноническая карта слоёв зафиксирована в [архитектуре репозитория](REPOSITORY_ARCHITECTURE.md), а нумерованные каталоги `docs/01`–`docs/08` остаются единственными тематическими точками входа. Этот профиль не создаёт параллельные ненумерованные каталоги и не переносит существующие главы.

## Математические границы

- Единственный канонический источник базовой теории — `docs/VYUNENKO_THEORY.md`; навигационные README не являются альтернативными версиями теории.
- Основание (B=1000), коэффициенты (0\ldots999), позиционный порядок и лексический разделитель `k` сохраняют семантику действующего математического контракта.
- Позиции каскадных блоков, нулевые группы и разделители нельзя переставлять, удалять или нормализовать без доказательства эквивалентности.
- Вычислительный код, контрольные векторы и CI подтверждают только результаты в явно объявленной области; они не заменяют универсальное математическое доказательство.
- Гипотеза, доказанная теорема, конечная проверка, вычислительное наблюдение и прикладная модель сохраняют разные эпистемические статусы.
- Связи с DAK, Reaper, Pytyliki, OPlague и VentuSample остаются математическими отображениями и не расширяют предметную область Kaskad до продуктовой разработки.
- Каталог `formal/` не объявляет машинную формализацию до появления реального проекта, зафиксированного инструментария и исполняемой проверки.

## Правило изменения путей

Перемещение главы должно обновлять все входящие ссылки, `docs/INDEX.md`, тематические README 01–08, архитектуру репозитория, скрипты синхронизации, проверки Markdown, CI и доказательные ссылки в одном reviewable PR. Канонические файлы не дублировать. Новую категорию сначала согласовывать с `docs/REPOSITORY_ARCHITECTURE.md`, а не вводить параллельным каталогом.

## Проверка

`scripts/verify_repository_structure.sh` проверяет существование канонических каталогов и индексных README Kaskad, а также наличие их навигационных ссылок в `docs/INDEX.md`. Эта проверка структуры не является проверкой доказательств или математической истинности.
