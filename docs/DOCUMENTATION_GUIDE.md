# Руководство по документации Kaskad

> **Тип:** редакционно-методологическое руководство.  
> **Дата редакции:** 28 ноября 2026 года.  
> **Статус:** правило организации корпуса; не является аксиомой K3 и не подтверждает теорем.  
> **Нормативная основа:** [Cascade Edition 1.0.0](SCIENTIFIC_MATHEMATICAL_DOCUMENTATION_STANDARD.md).

Руководство задаёт единый маршрут по материалам Kaskad и предотвращает конкурирующие определения. Каждый предметный вопрос имеет один основной документ; остальные материалы ссылаются на него и уточняют собственную часть.

## 1. Иерархия источников

| Уровень | Документ | Ответственность |
|---|---|---|
| Обзор | [README](../README.md) | Кратко объясняет предмет, модель, границы и навигацию |
| Канон | [Теория Вьюненко K3](VYUNENKO_THEORY.md) | Определяет предмет, постулаты и фундаментальные результаты |
| Синтаксис | [K3_CANONICAL_SYNTAX](K3_CANONICAL_SYNTAX.md) | Задаёт допустимые слова, группы, разделители и режимы разбора |
| Арифметика | [Основания и алгебра](K3_CANONICAL_FOUNDATIONS_AND_ALGEBRA.md), [каскадный баланс](CHAPTER_II_CASCADE_BALANCE.md) | Описывает операции, переносы, заёмы и инварианты |
| Расширения | Профильные документы CRT, топологии, комбинаторики и структурной семантики | Вводят дополнительные объекты, не меняя конечное ядро без обоснования |
| Прикладные модели | Документы DAK, Reaper, Pytyliki, VentuSample, OPlague | Задают типизированные соответствия вне аксиоматики K3 |

При конфликте сначала проверяется область действия утверждений. Для синтаксиса приоритетна нормативная грамматика; для базовых объектов — каноническая теория; для конкретной операции — профильная глава вместе с её предпосылками. Навигационная таблица не переопределяет математику.

## 2. Нормативная нотация

- Основание: (B=1000=2^3cdot5^3).
- Канонические коэффициенты: (D_B={0,ldots,999}).
- Индекс (0) — младшая позиция; оценка: (sum_i a_iB^i).
- Символ `k` — разделитель соседних групп, не основание и не множитель.
- Оператор позиционного сдвига (S_B) отделён от разделителя.
- Нулевой коэффициент и его позиция входят в структуру. Их нельзя удалять или переставлять без доказательства сохраняемого соответствия.
- Канонический разбор, импорт K3-PAD и структурный вход K3-RAW — разные контракты.
- Ноль, пустая последовательность, пустое множество, отсутствующее и неопределённое значения не отождествляются.

## 3. Разделение математических уровней

Для преобразования указываются входной тип, операция, выходной тип и сохраняемые инварианты. Различаются:

1. равенство исходных строк;
2. равенство коэффициентных структур;
3. равенство числовых значений;
4. равенство упорядоченных деревьев выражений;
5. равенство операционных следов.

Из совпадения значений не следует равенство представлений, порядка или истории вычисления. Нормализация разрешена только в объявленном режиме и должна сохранять точно указанную величину.

## 4. Статусы утверждений

| Статус | Смысл | Требование |
|---|---|---|
| Определение | Вводит тип, множество или отображение | Явная область и правила |
| Постулат | Фиксирует исходное соглашение | Не выдаётся за доказанный факт |
| Теорема / следствие | Универсальное математическое утверждение | Полная формулировка и доказательство |
| Классический результат | Положение из известной теории | Источник и условия применения |
| Вычислительная проверка | Тест или конечный перебор | Ревизия, входы, область и результат |
| Спецификация / проект | Предлагаемая модель или требование | Не объявляется реализацией |
| Гипотеза / открытая задача | Неустановленное утверждение | Явные доказательные обязательства |
| Факт реализации | Поведение существующего артефакта | Путь, ревизия и воспроизводимая проверка |

Тест подтверждает только реально исполненные случаи. Конечный перебор не доказывает автоматически утверждение о бесконечной области. Отсутствие результата CI означает «не проверено», а не «успешно».

## 5. Правило против дублирования

- Полное определение записывается один раз — в документе-владельце темы.
- В README и обзорах остаются краткое объяснение и ссылка на первичный раздел.
- При изменении сначала обновляется документ-владелец, затем связанные главы, векторы, JSON-контракты, тесты и переводы.
- Новое расширение получает собственную область определения, статус и зависимости; оно не переопределяет ядро молча.
- Пример сопровождается режимом входа, разбором, коэффициентами и ожидаемым значением. Нулевые позиции записываются явно.
- Ссылки на реализацию, CI, публикации, DOI и измерения добавляются только после проверки фактического существования.

## 6. Контроль изменений

1. Найти документ-владелец и проверить его предпосылки.
2. Сверить обозначения, индексы, нули, режимы и уровни равенства.
3. Проверить формулы и добавить граничные примеры или контрпримеры.
4. Согласовать профильные главы, [INDEX](INDEX.md), [языковой реестр](LANGUAGE_REGISTER.md), схемы и эталонные векторы.
5. Выполнить доступные тесты и CI; записать точную ревизию и фактический статус.
6. Проверить ссылки, лицензии, происхождение материалов и смысловую эквивалентность переводов.

Полный набор научных требований приведён в [стандарте математической документации](SCIENTIFIC_MATHEMATICAL_DOCUMENTATION_STANDARD.md). Это руководство отвечает за навигацию и согласование корпуса.
