## 3. Правило математического покрытия

Каждый файл должен получить одну основную классификацию и при необходимости несколько дополнительных связей. Для файла с математическим содержанием фиксируются: точный источник; домен и кодомен; тип каждой координаты; единицы; порядок и позиции; нулевые/отсутствующие/неизвестные значения; предусловия; постусловия; инварианты; отрицательные примеры; зрелость; evidence; связанные файлы и версия контракта.

Файл, который является только локализацией, графическим ресурсом, лицензией, скриптом упаковки или внешним кодом, не нужно искусственно превращать в арифметическую теорему. Его смысл сохраняется в графе происхождения, визуальной/геометрической модели, воспроизводимости или правовой границе.

## 4. Статус полноты

Этот реестр подтверждает инвентаризацию путей и назначение дальнейшей формализации. Он не означает, что все 340 файлов уже прошли построчную математическую ревизию, независимое доказательство или runtime verification. Текущий математический слой подробно формализует основные контракты и инварианты; дальнейшие проходы должны закрывать каждую схему, каждый тест, каждый нативный артефакт и каждый документ с отдельным evidence.

## 5. Связь с K3

Числовые координаты кодируются по K3 с основанием 1000 и коэффициентами 0..999. Составные записи остаются типизированными структурами. Нельзя сворачивать весь файл, JSON schema, граф или автомат в одно число, удалять нули/пустые позиции либо менять порядок полей без доказательства сохранения смысла.
