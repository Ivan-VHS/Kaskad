## Призначення та межі

Kaskad — постійний математичний дослідницький корпус. Його основний предмет —
Теорія В'юненка K3 та строго визначені математичні розширення. Робочий цикл:

**питання → класичний математичний контекст → означення → модель →
доведення або контрприклад → точна чи чисельна перевірка наслідків →
незалежна перевірка → документування результату.**

Kaskad не є проєктом операційної системи, мови програмування, IDE, драйверів,
прикладних програм або універсальної програмної платформи. Зв'язки з іншими
репозиторіями допускаються лише як математичні відношення: спільні
означення, відображення, моделі, довідні наслідки та аналогії з явно
зазначеними межами.

Код і обчислювальні інструменти можуть використовуватися як допоміжні засоби
для точної арифметики, скінченної перевірки, відтворюваних експериментів,
перевірки документів або формальної верифікації. Обчислення не замінює
математичного доведення і саме по собі не перетворює гіпотезу на теорему.

## Математична модель K3

У базовій системі зафіксовано складену основу

\[
B=1000=10^3=2^3\cdot5^3.
\]

Канонічний каскад задається скінченним вектором коефіцієнтів

\[
a=(a_m,\ldots,a_1,a_0),\qquad a_i\in\{0,1,\ldots,999\},
\]

а його числове значення визначається поліноміальною оцінкою

\[
\operatorname{Val}_{K3}(a)=\sum_{i=0}^{m}a_iB^i.
\]

Індекс \(i=0\) відповідає молодшій групі. У текстовому записі групи
розділяються символом \(\mathtt{k}\). Символ \(\mathtt{k}\) є лексичним
роздільником груп, а не цифрою, множником чи оператором множення.
Оператор позиційного зсуву \(S_B\) визначається окремо.

| Параметр | Канонічне значення |
|---|---|
| Система | K3 |
| Основа | \(B=1000=2^3\cdot5^3\) |
| Діапазон канонічної групи | \(0\ldots999\) |
| Роздільник груп | \(\mathtt{k}\) |
| Область невід'ємних значень | \(\mathbb N_0\) |
| Знакове розширення | \(\mathbb Z\) |
| Канонічне слово нуля | \(0\) |
| Порожнє слово | Не є канонічним поданням |

Канонічні невід'ємні каскади представляють \(\mathbb N_0\); знакове
розширення окремо розглядається для \(\mathbb Z\). Оскільки основа складена,
властивості простих \(p\)-адичних основ не можна переносити на K3 без
доведення. На рівні \(r\) використовується розклад

\[
\mathbb Z/1000^r\mathbb Z
\cong
\mathbb Z/2^{3r}\mathbb Z\times\mathbb Z/5^{3r}\mathbb Z,
\]

а відповідне поповнення описується як топологічне кільце
\(\mathbb Z_2\times\mathbb Z_5\), а не як поле.

## Епістемічний статус тверджень

Документи розрізняють означення, постулати, припущення, леми, теореми,
наслідки, гіпотези, контрприклади, вичерпну скінченну перевірку,
обчислювальні та емпіричні спостереження, чисельні оцінки, евристики,
умовні результати, відхилені формулювання й дослідницькі програми.

Наявність пункту в дорожній карті не означає, що результат доведений.
Скінченний перебір підтверджує твердження лише на повністю перебраній
скінченній області. Емпірична закономірність або чисельна оцінка не є
універсальним доведенням. Текстові доведення не можна називати машинно
формалізованими, доки відповідну формалізацію не опубліковано.

## Відтворювана перевірка

Поточний CI перевіряє узгодженість контрактів проєкту й математики,
канонічну семантику K3, обов'язкові документи та відносні посилання README.
Це перевірка документації й контрактів, а не машинна перевірка математичних
доведень і не набір тестів математичного обчислювального ядра.

Для локального запуску потрібен Node.js 22 — саме цю основну версію задає
поточний workflow CI. Скрипт використовує вбудовані модулі Node.js;
встановлювати пакети не потрібно.

~~~bash
git clone https://github.com/Ivan-VHS/Kaskad.git
cd Kaskad
node --version
node scripts/validate-foundation.mjs
~~~

Очікуваний результат за коректних контрактів і локальних посилань:

~~~text
Kaskad mathematical scope, K3 notation, algebraic semantics, arithmetic contracts and local links: OK
~~~

Workflow використовує GitHub-hosted runner з міткою ubuntu-latest,
actions/checkout v4 та actions/setup-node v4. Це опис поточної конфігурації CI,
а не повністю зафіксоване середовище чисельного наукового експерименту.
Для дослідницьких обчислень слід фіксувати точні версії інструментів,
ревізію джерел, параметри точності й округлення, вхідні дані та їхні
SHA-256, а для стохастичних процедур — PRNG і seed.

## Інтегровані математичні розширення (2026-11-28)
